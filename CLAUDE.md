## Project Overview

This is a React Router v7 application deployed on **Cloudflare Workers** that displays open procurement opportunities from multiple Bonfire Hub agency portals. The app uses server-side rendering (SSR) and is built with TypeScript, TailwindCSS v4, and shadcn/ui components. It uses **D1** (SQLite) for persistent caching and **KV** for fast API response caching.

## Development Commands

This project uses **Bun** as the package manager (`bun.lockb` present):

```bash
# Install dependencies (also runs wrangler types via postinstall)
bun install

# Start development server (runs on http://localhost:5173 with miniflare for D1/KV)
bun run dev

# Type checking (generates React Router types and runs TypeScript compiler)
bun run typecheck

# Generate Cloudflare binding types
bun run cf-typegen

# Production build
bun run build

# Start local production server via wrangler
bun run start

# Deploy to Cloudflare Workers
bun run deploy

# D1 database migrations
bun run db:migrate         # Apply locally
bun run db:migrate:prod    # Apply to production
```

## Architecture

### Runtime: Cloudflare Workers

- **Adapter**: `@react-router/cloudflare` bridges React Router v7 to Workers runtime
- **Entry point**: `workers/app.ts` — CF Workers `fetch` handler that passes `env` (D1, KV) into React Router's `AppLoadContext`, plus a `scheduled` (cron) handler that runs the cache warmer
- **Server entry**: `app/entry.server.tsx` — SSR rendering using `renderToReadableStream`
- **Dev proxy**: `cloudflareDevProxy()` in `vite.config.ts` provides D1/KV bindings during local dev via miniflare
- **Config**: `wrangler.jsonc` — Workers name, D1/KV bindings, compatibility settings
- **Types**: `worker-configuration.d.ts` — auto-generated by `wrangler types`, defines `Env` interface

### Caching / Data Strategy

**Why this is unusual:** all ~70 agency portals share one Cloudflare-protected
`*.bonfirehub.com` backend with a strict, shared rate limit. Fetching them all
on a user request (in parallel, or even throttled) trips the limit and returns
HTTP 429 from Workers' datacenter IPs. So fetching is fully decoupled from page
requests:

- **Background cache warmer** (`app/lib/cache-warmer.ts`): invoked by the
  `scheduled` (cron) handler every minute. Fetches a small rotating batch of
  agencies **one at a time** with pacing + 429 backoff, staying under the shared
  rate limit. A cursor in **KV** (`warmer:cursor`) tracks progress so successive
  ticks cycle through all agencies (~14 min full cycle at batch size 5). Tunable
  via constants at the top of `cache-warmer.ts`.
- **D1 is the source of truth** (`app/lib/cache-store.ts`): the warmer writes
  successful fetches to the `agency_cache` table; the loader reads everything in
  one query. Last-known-good data persists across rate-limited cycles.
- **Loader reads D1 only** (`app/routes/home.tsx`): user requests never hit
  bonfirehub, so they're instant (~0.5s) and can't be rate-limited. Agencies the
  warmer hasn't reached yet show no opportunities (not an error) until cached.
- **`app/lib/api-client.ts`**: single-agency fetch only (`fetchAgencyData`), used
  by the warmer. Browser-like headers; 429 is deliberately NOT retried (retrying
  spends more of the shared rate budget).
- **D1 schema** (`migrations/`): `agency_cache` and `opportunities_history` tables.

### React Router v7 Configuration

- **Routes**: Defined in `app/routes.ts` using the `@react-router/dev/routes` API (not file-based routing)
- **Route modules**: Live in `app/routes/` directory (e.g., `app/routes/home.tsx`)
- **Type generation**: React Router auto-generates route types in `.react-router/types/` directory
- **Route typing**: Import types from `./+types/[route-name]` for loaders, meta, and components

### Key Patterns

**Loaders with Cloudflare context**: Use `loader` functions that access CF bindings via `context.cloudflare.env`:

```typescript
export async function loader({ request, context }: Route.LoaderArgs) {
  const { env } = context.cloudflare;
  const cached = await readCachedAgencies(env.DB); // read-only; no network
  return data;
}
```

**Meta tags**: Export a `meta` function typed with `Route.MetaArgs`:

```typescript
export function meta({}: Route.MetaArgs) {
  return [
    { title: "Page Title" },
    { name: "description", content: "..." }
  ];
}
```

**Path aliases**: Use `~/` prefix to import from the `app/` directory:
- `~/components/ui/button` → `app/components/ui/button.tsx`
- `~/lib/utils` → `app/lib/utils.ts`

### Application-Specific Features

**Agency Configuration** (`app/config/agencies.ts`):
- 50+ agencies organized by category (state, county, city, university, etc.)
- Each agency has: name, apiUrl, baseUrl, category
- Categories enable grouped dropdowns and filtering

**Data Fetching** (see "Caching / Data Strategy" above):
- `fetchAgencyData()` (`app/lib/api-client.ts`) - fetches ONE agency; never throws (failures returned as `AgencyData` with `error` set)
- `warmCache()` (`app/lib/cache-warmer.ts`) - cron-driven; the only caller of `fetchAgencyData`, paced to avoid 429s
- `readCachedAgencies()` (`app/lib/cache-store.ts`) - the loader's read path; returns cached `AgencyData` keyed by agency name
- Do NOT fetch bonfirehub from a loader/user request — it will be rate-limited (HTTP 429)

**Filtering & Sorting** (`app/lib/project-utils.ts`):
- `filterProjects()` - Search by project name, reference ID, description
- `filterByClosingDate()` - Filter by days until close (3, 7, 14, 30)
- `sortProjects()` - Sort by close date, open date, agency name
- All filters and sorts are composable

**Date Utilities** (`app/lib/date-utils.ts`):
- `formatCloseDate()` - Human-readable dates
- `getRelativeDate()` - "in 3 days", "tomorrow", etc.
- `isClosingSoon()` - Urgency detection (< 3 days)
- `getDaysUntilClose()` - Calculate remaining days

**Export** (`app/lib/export-utils.ts`):
- `exportProjectsToCSV()` - Export filtered results to CSV
- Includes: agency, project name, reference ID, department, dates, link
- Downloads as `opportunities-YYYY-MM-DD.csv`

**Dark Mode** (`app/lib/use-dark-mode.ts`):
- `useDarkMode()` hook with localStorage persistence
- Respects system preference as default
- Toggles `dark` class on document root

**View Modes**:
- Single agency view: View projects from one agency
- All agencies view: Browse all opportunities across all agencies
- Agency name shown on cards in "All Agencies" mode

**Pagination**:
- Initial load: 20 items
- "Load More" button for additional 20 items
- Auto-reset when filters change
- Improves performance with large datasets

**SSR Configuration**: Server-side rendering enabled in `react-router.config.ts`

## Deployment

Deployed via Cloudflare Workers using `wrangler deploy`. No Docker needed.

### CF Resource Provisioning (one-time setup)

```bash
wrangler d1 create bonfire-cache          # Create D1 database
wrangler kv namespace create KV           # Create KV namespace
# Update wrangler.jsonc with returned IDs
bun run db:migrate:prod                   # Apply D1 migrations to production
```
